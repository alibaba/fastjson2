## fastjson2 精简评估(纯 JSON 树模式)

用户需求:仅保留 org.json 风格 API(JSONObject/JSONArray 的解析与生成),不做 Java Bean / Map / List 序列化反序列化。

**现状(分支 develop-slim,2.0.63 基线)**:123 文件 / 83,275 行。autotype 已去除,但 reader/writer/introspect/annotation/codec/modules/filter/function 反射体系完整保留(约 88 文件 / 22,400 行可删)。

**关键发现**(带行号,便于后续实施):
- 解析主路径 `JSONReader.read(Map,0L)` (JSONReader.java:3143) 手写 switch 递归,不依赖 provider;仅 `readAny()` (3575→3384) 和 `readArray()` (3767) 依赖 provider;`read(Map,long)` 内仅 2 处:L3280 read(HashSet.class)、L3254 typeRedirect 分支(已不可达)。
- 生成主路径 `JSONWriter.write(Map)` (2836) / `write(List)` 内建,features==0 时 JSONObject.toString 不经过 provider;仅 `writeAny` (2941→2948) 依赖。
- JSONObject.getJSONObject(String) L314 / getJSONArray L239 用静态 OBJECT_READER/arrayReader,可改 `JSON.parseObject/parseArray` 消除依赖。
- JSONObject/JSONArray 的 toJavaObject 系列(L1190-1463 / L1121-1432)整体可删。
- JSONFactory 的 PROPERTY_ACCESSOR_FACTORY (95,219-232) 已确认死代码;ObjectWriterException 无抛出点。
- JSON.java 方法已全部包级私有(安全处理),可继续删 Bean 重载。

**精简方案**:保留 ~35 文件 / ~3 万行(JSON/JSONObject/JSONArray/JSONFactory/JSONReader×3/JSONWriter×5/SymbolTable/util: IOUtils·Fnv·JDKUtils·TypeUtils精简·MutableBigInteger);整体删除 annotation(6)/codec(3)/modules(5)/filter(18)/function(14)/internal(2)/introspect(8)/reader·writer 反射实现(8)/util Bean 工具 14 个(BeanUtils·DateUtils·StringUtils·Scientific·FDBigInteger·NumberUtils·JdbcSupport·DynamicClassLoader·PropertiesUtils·ED*·ReferenceKey·Wrapper·MultiType·MapMultiValueType·ParameterizedTypeImpl)/TypeReference/PropertyNamingStrategy。
两个方案:方案 A 保留 ObjectReader/ObjectWriter 接口+极简 Provider(改动小);方案 B 彻底删 reader/writer 包,readAny/writeAny 手写(最干净)。报告已写入 docs/精简评估报告.md。

## 精简实施完成(22:50)

按方案 B 完成纯 JSON 树模式精简,最终 32 文件 / 41,018 行(原 123 / 83,275,-74%/-51%),jar 358KB,133 测试通过。

关键决策与经验:
- **彻底删除反射体系**:reader/writer/introspect/annotation/codec/modules/filter/function/internal 10 包 + TypeReference + PropertyNamingStrategy + util Bean 工具(BeanUtils/DateUtils/JdbcSupport 等)
- **删除 Date/UUID**:JSONReader/JSONWriter 及子类全部时间方法 + DateUtils(9311行)
- **JSONReader.readAny 手写 switch 递归**,JSONWriter.writeAny 改 instanceof,JSONObject.getJSONObject/getJSONArray 改 JSON.parseObject/parseArray
- **JSONFactory 重写**:删 provider;保留 CacheItem/NAME_CACHE/DIGITS2/NIBBLES/FLOAT_10_POW/DOUBLE_10_POW/defaultDecimalMaxScale(被 Reader/Writer 引用,重写时勿删)
- **util 保留**:IOUtils/Fnv/JDKUtils/TypeUtils(裁剪)/NumberUtils/ED/ED5/EF/Scientific/FDBigInteger/MutableBigInteger/StringUtils/ParameterizedTypeImpl(去注解)/Wrapper —— 数字解析核心
- **JSON.java 方法必须 public**(OSGi 项目调用)
- 工具链:Python 花括号匹配删除方法脚本(需正确处理单引号字符字面量与注释,否则 UTF16 会被破坏;行号删除易偏移,删前先备份)、git checkout 恢复、孤儿 @Override/@SuppressWarnings 清理脚本
- 子类 UTF8/UTF16 覆盖 write(Map)/write(List),需补 Double/Float/Short/Byte/Character 分支,兜底抛 JSONException
- PrettyFormat 输出格式为 "key":value(冒号无空格)

坑:行号删除在多次删除后偏移导致方法边界破坏;测试文件大量引用已删 API 需同步清理。

## IDE 警告二轮清理(23:00)

上一轮盲加 @SuppressWarnings 产生大量 Unnecessary 新警告。二轮改为数据驱动:
- 关键教训:1) javac 的 "Unsafe 内部 API" 警告用 @SuppressWarnings("sunapi") 无效(javac 不认 sunapi 键),靠 pom 的 -XDignore.symbol.file;2) Eclipse JDT 的 Access restriction 用 @SuppressWarnings("restriction") 抑制;3) 类级注解只能给"真有警告"的类加,否则 JDT 报 Unnecessary
- 方法:移除全部注解 → javac -Xlint:rawtypes,unchecked 统计 → 精准加注解(7 文件)+ 修代码(JSONObject/JSONArray/JSON 的少量 raw type)
- 删 java.time.* 等 20 个 unused import;修未使用局部变量/方法;NotWriteEmptyArray deprecated 用类级 deprecation
- 最终:mvn BUILD SUCCESS、133 测试全绿
