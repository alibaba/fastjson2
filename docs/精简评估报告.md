## 2. 核心发现:树解析/生成主路径其实不依赖反射体系

这是本次评估最重要的结论 —— 纯 JSON 树模式**不需要** ObjectReader / ObjectWriter 反射体系,只需处理 4 个耦合点:

### 2.1 解析路径(JSONReader)
- `JSON.parseObject(String)` → `reader.read(Map, 0L)`(JSONReader.java:3143):手写 switch 递归,数字/字符串/数组/对象均内建,**不经过 provider**。
- `readArray()`(3767)与 `readAny()`(3575 → 3384 `read(Object.class)`)是仅有的两个依赖 provider 的入口,用于递归解析嵌套值。
- `read(Map, long)` 中仅 2 处依赖 provider:
  - L3280 `read(HashSet.class)`('S' 开头的 Set 场景,树模式可去掉)
  - L3254 `typeRedirect` 分支(@type 已死,此分支已不可达,可删)

### 2.2 生成路径(JSONWriter)
- `JSONObject.toString()` 默认(features==0)走 `write(Map)`(JSONWriter.java:2836)内建遍历,**不经过 provider**。
- `JSONArray.toString()` 同理走 `write(List)`。
- 仅 `writeAny(Object)`(2941 → 2948 `context.getObjectWriter`)依赖 provider,且只在值类型不是 JSONObject/JSONArray/Map/List/String/Number/Boolean 时才会触发。

### 2.3 JSONObject / JSONArray 内的静态 reader/writer
- `JSONObject.getJSONObject(String)`(L314)与 `getJSONArray(String)`(L239)用静态 `OBJECT_READER` / `arrayReader` 解析**字符串形式的嵌套 JSON** —— 可直接改为 `JSON.parseObject(str)` / `JSON.parseArray(str)`,彻底消除依赖。
- `toJavaObject` / `getObject(Class)` / `toList(Class)` 系列(JSONObject L1190-1463,JSONArray L1121-1432)全部经 provider —— 按需求**整体删除**。

## 5. 两个实施路径(建议先 B 后 A 或直接 A)

### 方案 A(推荐):保留 2 个接口 + 极简 Provider
- 保留 `ObjectReader` / `ObjectWriter` 接口(各 300-400 行),Provider 只注册 6 种内置类型。
- 删 Creator / BaseModule / Objects 等全部反射实现。
- **优点**:`readAny()` / `writeAny()` 和递归解析逻辑几乎不用改,改动集中在「删」,编译通过率高、回归风险低。
- **缺点**:仍保留少量抽象层。

### 方案 B(最干净):彻底删除 reader/writer 包
- `JSONReader.readAny()` 改为手写递归(参考 `read(Map, 0L)` 的 switch 逻辑),直接返回 JSONObject/JSONArray/基本类型。
- `JSONWriter.writeAny()` 改为 `instanceof` switch。
- `JSONObject.getJSONObject/getJSONArray` 改用 `JSON.parseObject/parseArray`。
- **优点**:没有任何 Object* 抽象,攻面最小,与 org.json 的纯粹性一致。
- **缺点**:需动 `readAny` / `writeAny` / Context 三处核心逻辑,工作量稍大。

## 6. 建议的实施顺序

1. **删**:`annotation/`、`codec/`、`modules/`、`function/`、`filter/`、`internal/`、`introspect/`(这 7 个包无互相依赖的反射实现,删完跑一次编译)。
2. **删**:`util/` 中 BeanUtils / DateUtils / StringUtils / JdbcSupport / DynamicClassLoader / PropertiesUtils / Scientific / FDBigInteger / JSONObject1O / ReferenceKey / Wrapper / ED* / MultiType / MapMultiValueType / ParameterizedTypeImpl(删完处理编译报错,多为 import 清理)。
3. **改**:JSONObject / JSONArray(删 toJavaObject 等泛型方法;getJSONObject/getJSONArray 改走树解析;删静态 reader/writer 字段)。
4. **改**:JSONReader / JSONWriter(readAny/writeAny 去 provider;删泛型重载;删 HashSet/typeRedirect/filter 字段)。
5. **收尾**:JSONFactory / JSON / TypeUtils / IOUtils 清理死代码,统一异常与 features。

每步都以 `mvn -pl core compile` 和现有 31 个测试文件验证。

## 7. 风险提示

- **行为差异**:`JSONObject.toString()` 默认对 `Date`、`UUID` 等非基本类型不再支持(方案 B 直接抛异常,方案 A 按字符串输出)——若业务中混入这些值需先确认。
- **`getJSONObject(String)` 的字符串解析**:现实现用 OBJECT_READER 解析,改造为 `JSON.parseObject` 后行为等价,但注意 `str.isEmpty()` / `"null"` 的短路判断需保留。
- **features 裁剪**:`JSONReader.Feature` / `JSONWriter.Feature` 中与 Bean 相关的枚举(如 FieldBased、IgnoreNoneSerializable)删除后,若外部代码引用会编译失败,属预期。
- **JDK8 变体**:JSONWriterUTF16JDK8/8UF/9UF 涉及 Unsafe,删除前确认 `of()` 工厂的选型分支,避免运行时 NPE。
